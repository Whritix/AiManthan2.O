# Five-product inspection scope

The upload workflow accepts only steel, screw, metal nut, transistor, and bottle as product families. An internal `other` class is used solely to reject out-of-scope images; it is not an inspection profile and no defects are reported for it. Normally, uncertain and nonfinite identifier predictions are rejected before YOLO runs. A narrow exception handles classifier scores from 0.45 to 0.55 when the top candidate is supported **and** the local VLM independently names the same product with at least two visible cues and no stated uncertainty. The API marks this `vlm_confirmed` and attaches a domain warning. Even if YOLO finds no defects, the inspection routes to **human review**, and the reuse/recycle advisor requires manual inspection. If the VLM is unavailable or disagrees, the upload stays rejected. Uploaded videos are routed from their first decoded frame.

The active product classifier is `artifacts/models/auto_profile_classifier.joblib`. The prior five-way classifier is preserved as `auto_profile_classifier_fiveonly_backup.joblib`. Rebuild the scoped candidate with `python scripts/train_auto_profile_scope.py`; review `artifacts/eval/auto_profile_scope_candidate.json` before copying the candidate over the active model.

On the existing supported-family evaluation split, the scoped model correctly accepted 97.5% of images. It rejected 96.1% of the available MVTec out-of-scope evaluation images. All ten guided demo images routed to the intended family. These figures do not include the new VLM exception. Its accuracy is unmeasured, and it does not validate defect detection on new package styles, backgrounds, or camera conditions. Collect examples from the intended upload setting to measure those errors.
